# Cheaper ticks, part 2: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring a fullscreen tick on the slow cores from about 700 ms to under 350 ms,
so MapleLens reads faster than its 500 ms tick and the UI thread is free part of the time.

**Architecture:** (1) On a Retina Mac, capture the game at its own size: it draws at
1512x850 (fullscreen) or 1366x768 (windowed) and macOS doubles it, so half the pixels
carry all of it. Grab, black-bar trimming and `normalize` all shrink, and windowed play
becomes pixel-exact. (2) Search for a closed window on a half-size image first, then
confirm at full size only where it scored. (3) Search for the minimap's title once per
tick, not twice.

**Tech Stack:** Python 3, numpy, OpenCV, pyobjc (Quartz), PySide6, pytest.

**Spec:** none. Part 1 is `docs/superpowers/plans/2026-11-12-tick-cost.md` (same branch);
this plan argues from the live measurements below.

## Global Constraints

- Screen-only (`AGENTS.md`): read pixels only. Don't write the guard's banned names in
  comments or docstrings under `src/` or `scripts/`.
- Readers stay pure `frame -> value` functions tested on cropped PNG fixtures; a warm
  cache must give the same value as a cold one.
- Each tool depends only on readers and overlay. No tool changes in this plan.
- No new dependency. Never change `version` in `pyproject.toml`.
- Never commit the owner's grabs: they show the character's name and chat. Derive test
  images from the committed fixtures instead.
- Windows behaviour must not change: `capture_win` keeps returning the client area at
  full size.
- One capturer at a time while measuring live (two make `CGWindowListCreateImage` hang
  about 30 s): quit MapleLens before running a capture experiment.

## What was measured live (2026-11-12, fullscreen 3024x1700, MapleStory in front)

Same tracer on both (it times what MapleLens does, captures nothing extra), about 4.5
minutes each; the slow cores ran about 10.5x slower than full speed.

| median | main | part 1 (this branch) |
|---|---|---|
| tick | 2,183 ms | 701 ms |
| `read_all` | 1,914 ms | 436 ms |
| readings per second | 0.46 | 1.22 |

Part 1's tick, per part (slow cores): grab about 200 ms and `picture_box` 40 ms (capture
is now a third of the tick); `normalize` 96 ms; the closed-window search on its turn
+100 ms (quest), +220 ms (stats), +320 ms (skills); the open tracker 29 ms; the map name
when the minimap is closed 205 ms (37 ticks); the rest under 25 ms.

Capture at full speed, the game in front, measured with a one-off script:

| | today (3024x1964) | `kCGWindowImageNominalResolution` (1512x982) |
|---|---|---|
| `CGWindowListCreateImage` | 18 ms | 17 ms |
| draw into the bitmap | 32 ms | 10 ms |
| `picture_box` | 8.0 ms | 2.3 ms |
| `normalize` | 9.1 ms | 3.8 ms |

On a live fullscreen grab the nominal image was pixel-identical to every second pixel of
today's (status bar rows, all four phases). The four fullscreen fixtures are exactly
doubled too (one phase each: `exp_*` rows from 1, columns from 0; `level_a` from 0, 0).
Windowed play was **not** checked: there the game can sit half a point low (`game_top`),
and a nominal capture of that may blend rows.

Half-size coarse search (Part 1's notes): all six window anchors 28 ms instead of 140 at
full speed, scores higher (tracker 0.64 → 0.80), the best spot within 1 px of the full one.

### Task 0's live checks (2026-11-12, the owner playing)

**A helper process escapes the slowdown.** With the game fullscreen in front:

| at the same moment | `normalize` median |
|---|---|
| MapleLens (part 1), App Nap opted out (`beginActivityWithOptions` user-initiated), 205 ticks | 95 ms |
| a plain Python process started while that MapleLens ran | 9.2 ms |
| a small Qt test app's child process (two runs) | 9.2 ms |

Opting out of App Nap changed nothing (95 ms against 96 before), so it isn't App Nap.
The slowdown follows the MapleLens app, not every process. A small Qt test app was slowed on one
sample in 40 only, so it doesn't reproduce it. By Task 0's rule this gets its own plan:
[2026-11-12-tick-helper.md](2026-11-12-tick-helper.md). A prototype that did the grab
and the read in a child took the fullscreen tick from 701 to 170 ms. Tasks 1-3 wait for
part 3's numbers.

**Windowed, nominal capture: exact as far as seen, the odd phase never seen.** Four window
spots (1366x796 points), `game_top` phase 0 at every one: the nominal image matched the
full one's `[top::2, ::2]` on 99.9% of status-bar pixels (98% of the client area, which
moves between the two grabs). One spot, captured once, matched neither way (44%), likely
mid-drag. The half-point-low phase didn't occur, so a nominal capture of it is unchecked.
Ruling for Task 1 if it runs: **self-halving**, exact by construction in both phases.

   `test_crop_bgr_halves_from_the_games_top` pins the phase.

5. **A window opening during the half-size search**: found as often as by the full

### Task 1: Capture the game at its own size on a Retina Mac

**Files:**
- Modify: `src/maplelens/capture_mac.py` (`grab`, `crop_bgr`)
- Modify: `src/maplelens/app.py` (`Tick.run`: the picture box to rect pixels)
- Modify: `AGENTS.md` (capture line; fixture names carry the size `grab.py` saves)
- Test: `tests/test_capture_mac.py`, `tests/test_app.py`, `tests/test_readers.py`

**Interfaces:**
- Produces: `capture.grab(hwnd, rect) -> np.ndarray` may now be smaller than `rect`: on
  a Mac with backing scale 2 it is the game's own pixels, `rect[2] / 2` by `rect[3] / 2`.
  Everywhere else (Windows, scale 1) it is `rect`'s size, as today. `rect` stays in
  screen pixels.
- `Tick.run`: with `k = rect[2] / frame.shape[1]`, the trimmed rect is
  `(rect[0] + round(x * k), rect[1] + round(y * k), round(w * k), round(h * k))`.

- `crop_bgr(rgb, rect, half: bool = False) -> np.ndarray`; `grab` passes
  `half=True` when the window's screen has backing scale 2.

Which capture (Task 0, Step 2): **nominal**: `grab` adds
`kCGWindowImageNominalResolution` when halving, and `crop_bgr(..., half=True)` crops
`rect // 2` from the image (no `game_top`: the nominal image has no pairs).
**Self-halving**: `grab` captures as today and `crop_bgr(..., half=True)` returns
`out[::2, ::2]` after `game_top`, so the pairs start at the game's top.

- [ ] **Step 1: Write the failing tests:**
  - `test_crop_bgr_halves_from_the_games_top` (self-halving only): a synthetic doubled
    RGB image, one backing row low (as `test_crop_bgr_finds_game_one_retina_pixel_low`
    builds it); with scale 2 the result equals the undoubled source exactly.
  - `test_crop_bgr_keeps_full_size_when_not_halved` (the Review Focus's
    `test_grab_keeps_scale_1_frames`): `half=False` gives `rect`'s size, equal to
    today's result on the existing crop tests' images.
  - `test_a_tick_scales_the_picture_box_to_the_rect`: like
    `test_a_tick_leaves_fullscreen_black_bars_out` with `client_rect` 800x600 and a
    400x300 grab whose rows 25-274 are the picture: the tools get
    `(0, 50, 800, 500)`.
  - `test_read_fullscreen_half` (tests/test_readers.py), for the four `fullscreen_*`
    fixtures: halve each at its phase (`exp_*`: `[1::2, ::2]`, `level_a`: `[::2, ::2]`)
    and read with `_window_args`-style frame and native at scale 850 / 768: the same
    value as `FULLSCREEN`. Also record each glyph's best score and its lead over the
    next char, and assert they clear `SCALED_MIN` and `SCALED_MARGIN` (if one doesn't,
    stop and report: the constants were measured at 3024x1700).

### Task 2: Find a closed window on a half-size image first

**Files:**
- Modify: `src/maplelens/readers/window.py` (`align`'s coarse step)
- Test: `tests/test_readers.py`

**Interfaces:**
- Produces: `align(...)` unchanged in signature and result. New
  `_coarse(gray: np.ndarray, half: np.ndarray, name: str) -> tuple[float, tuple[int, int]]`
  (the anchor's coarse score and spot in the full-size grey frame, given that frame and
  its half), constant `HALF_SLACK = 3` (full-size px around the half-size peak), and a
  module cache of each anchor's half-size grey template.

The coarse step, per anchor: grey the frame once per `align` call and halve it
(`cv2.resize(..., fx=0.5, fy=0.5, interpolation=cv2.INTER_AREA)`); match the half-size
template; take its best spot; then match the full-size template in the full-size grey
frame only within `HALF_SLACK` px around twice that spot. That score and spot go on
exactly as today's full search result (`COARSE_MIN`, then the fine search). Only the
place searched at full size shrinks; the decision is still today's score.

- [ ] **Step 1: Write the failing tests:**
  - `test_coarse_half_finds_what_the_full_search_finds`: for every window fixture
    (`stat_*`, `skill_*`, `quest_*`, `tracker_*`, via `_window_args`) and each of its
    reader's anchors that scores ≥ `COARSE_MIN` in a full search (computed in the test
    with `cv2.matchTemplate` on the grey frame and `cv2.minMaxLoc`): `_coarse` gives the
    same spot and score. The existing window-reader tests then pin `align`'s results.
  - `test_coarse_half_looks_at_full_size_only_near_the_peak`: record
    `cv2.matchTemplate` calls during one coarse step: one half-size image of the whole
    frame, and full-size images no larger than the template plus `2 * HALF_SLACK`.
- [ ] **Step 2: Run them**, expected the second FAIL.
- [ ] **Step 3: Implement** the coarse step.
- [ ] **Step 4: Run all tests**, expected PASS, the align and window-reader tests among
  them. Profile the fullscreen grabs: `window.align` mean per tick at least 3x lower
  than before this task.
- [ ] **Step 5: Commit** `perf(readers): find a closed window on a half-size image first`.

## Not in this plan

- **A helper process** for capture and read: its own plan, if Task 0 Step 1 shows it
  runs at full speed.
- **Spacing ticks** (a single-shot timer restarted after each tick): ticks run back to
  back today (median gap 714 ms ≈ tick 701 ms), but spacing only trades readings for idle
  time; it doesn't shorten the wait for one click. Revisit if the box still feels stuck
  after this plan.
- **ScreenCaptureKit** instead of `CGWindowListCreateImage`: frames delivered off the UI
  thread, but a new framework binding (a dependency) and a larger change.
- **The quest window on fullscreen**: not opened in either live run, so unknown; Task 4
  checks it.
