# Cheaper ticks: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Do about a quarter of today's work per tick, so the overlay keeps up when macOS
runs MapleLens on the efficiency cores (fullscreen game in front, Game Mode).

**Architecture:** Three changes, each on its own. (1) `glyphs.find_anchor` looks near
its last spot first. (2) `window.align` checks an open window's last spot before it
searches the frame. (3) A window that isn't on screen is searched on one tick in four,
not on every tick: `Tick` tells `read_all` which readers are due. Nothing changes in
the tools.

**Tech Stack:** Python 3, numpy, OpenCV, PySide6, pytest.

**Spec:** none. This plan holds the measurements it argues from (below). It builds on
the fullscreen EXP fix (PR or-keren/maplelens#76, branch
`claude/exp-bar-reading-issue-3a3637`, commit 1f24823: `capture.picture_box`,
`glyphs.read_scaled`, `read_exp(img, frame)`). Branch from it
(`origin/claude/exp-bar-reading-issue-3a3637`), and rebase onto `main` once PR 76 merges.

## Global Constraints

- Screen-only (`AGENTS.md`): read pixels only. Don't write the guard's banned names in
  comments or docstrings under `src/` or `scripts/`.
- Readers stay pure `frame -> value` functions tested on cropped PNG fixtures. Module
  caches (as `glyphs._last_hit` is today) are allowed, but a warm cache must give the
  same value as a cold one.
- Each tool depends only on readers and overlay. No tool changes in this plan.
- No new dependency. Never change `version` in `pyproject.toml`.
- Never commit the owner's grabs (`~/Library/Application Support/MapleLens/grabs/`):
  they show the character's name and chat. Use them only through `scripts/profile_reads.py`.
- Profile with only one capturer running: two processes capturing the game window at
  once make `CGWindowListCreateImage` hang about 30 s. Profiling on saved frames needs
  no capture at all.

## What was measured (MacBook Pro M1 Pro, 2026-11-11/12)

Saved frames, `read_all` only (capture not included), the EXP-fix branch's code.

| | windowed 2732x1536 | fullscreen 3024x1700 | minimap closed (mac_2732x1536) |
|---|---|---|---|
| `read_all` today, performance cores | 147 ms | 254 ms (max 323) | 229 ms |
| prototype of Tasks 1-3, performance cores | 46 ms (max 54) | 67 ms (max 107) | 118 ms (4 slots, minimap not yet one) |
| today, efficiency cores (`taskpolicy -b`) | | 3,877 ms (15x) | |
| live, Game Mode (from the trace) | | 2,210 ms median (8.7x) | |

Fullscreen today, per tick: `window.align` 155 ms (4 calls), `glyphs.find_anchor` 79 ms
(5 calls), `normalize` 9 ms, `read_scaled` 9 ms, the rest under 10 ms. OCR costs nothing
in steady state (its caches hit).

- **`window.align`**: every call greys the frame and runs a full-frame
  `matchTemplate` per anchor, 20-27 ms each, six per tick (stat 2, skill 2, quest 1,
  tracker 1), open or not. A found window then runs the fine search, (2k+1)² native
  crops with k = ceil(2·scale): 121 at fullscreen, about 15 ms for the tracker.
- **`glyphs.find_anchor`**: its fast path needs a pixel-exact match. Fullscreen draws
  1512x850, which normalizes to no exact pixels, so all five anchors (EXP, level twice,
  minimap title twice) search their whole band every tick, every variant (3 each).
  An anchor that isn't there (minimap closed) also searches every tick: that's the
  229 ms of the third column.
- Half-resolution coarse search was tried: all six anchors take 28 ms instead of
  140 ms (only 5x, not 16x: OpenCV switches to a DFT for these sizes), and the
  scores move (the tracker 0.64 → 0.80), so `COARSE_MIN` would need recalibrating.
  Same gain as Task 3 with more risk: left out (see "Not in this plan").
- A 1 native px drag of a window lowers its anchor's exact-spot score by as little as
  0.015 (stat_a_2560x1440: 0.898 → 0.883). So "the score didn't drop" can't tell a
  moved window; Task 2 checks the 8 neighbouring starts instead.
- Found in passing: on the fullscreen grabs the tracker is found on 12 of 14 frames
  (its anchor's coarse score is 0.64, near `COARSE_MIN` 0.5, and its exact-spot score
  near `ANCHOR_MIN`). Today that flickers for one tick; Task 3's grace keeps it from
  flickering longer. Fixing the miss itself is a separate task.

## Targets

| | today | after Tasks 1-4 |
|---|---|---|
| fullscreen `read_all`, performance cores, median | 254 ms | ≤ 70 ms |
| windowed `read_all`, performance cores, median | 147 ms | ≤ 50 ms |
| fullscreen `read_all` at 8.7x (Game Mode), estimate | 2,210 ms | about 520-600 ms |
| a closed window opening is noticed within | 1 tick | 4 ticks (2 s) |

At Game Mode speed a tick still runs a little over `_TICK_MS`: readings come about once
a second instead of every 2-3 s. Task 6 checks it live and decides on the options below.

## Review Focus

1. **A window dragged by one native pixel while open**: the marks must follow it.
   Task 2 rejects the old spot when a neighbour scores higher (test
   `test_align_after_a_one_pixel_drag_matches_a_fresh_search`).
2. **The game resized, or switched between windowed and fullscreen, mid-run**: no cached
   spot from the old size may be used. Task 2 keys on the scale; Task 1's near box fails
   and searches again (tests `test_align_forgets_a_spot_from_another_scale`,
   `test_find_anchor_follows_a_moved_anchor`).
3. **A window opened while it was closed, or read only on some ticks**: it shows within
   4 ticks, and once seen a missed tick doesn't hide it (tests `test_due_*`).
4. **Warm caches across different screens**: the same readings as cold ones (test
   `test_read_all_warm_matches_cold`).
5. **One anchor of a window covered** (stat title hidden, bottom showing): the reuse of
   the title's spot fails and the full search finds the bottom
   (test `test_align_finds_the_other_anchor_when_the_last_one_is_covered`).

### Task 1: `find_anchor` looks near its last spot

**Files:**
- Modify: `src/maplelens/readers/glyphs.py` (`find_anchor`, `_last_hit`)
- Test: `tests/test_glyphs.py`

**Interfaces:**
- Produces: `find_anchor(frame, name, threshold=0.9)` unchanged in signature and result.
  New constant `NEAR = 2` (normalized px). `EXACT` goes.

The pixel-exact fast path becomes a near one: with a last hit at (x, y), match every
variant in `frame[y-NEAR : y+th+NEAR, x-NEAR : x+tw+NEAR]` (clipped to the frame). Take
the best score; accept it when it is ≥ `threshold` and its spot is inside the box, not
on its edge (a peak on the edge may continue outside: search the whole frame). On an
exact frame the old spot scores 1.0 and wins, as before. Else the full search, as today.

### Task 3: Search for a window that isn't there on one tick in four

**Files:**
- Modify: `src/maplelens/readers/__init__.py` (`read_all`; new `OPTIONAL`, `GRACE`,
  `due`, `found`)
- Modify: `src/maplelens/app.py` (`Tick`: fields `turn`, `seen_at`; `run`)
- Modify: `scripts/profile_reads.py` (read like the tick: `due` / `found`)
- Modify: `tests/test_app.py` (the `read_all` stand-ins take `due`)
- Test: `tests/test_readers.py`, `tests/test_app.py`

**Interfaces:**
- Produces, in `maplelens.readers`:
  - `OPTIONAL = ("stats", "skills", "quest", "tracker")`: the windows that may not be on
    screen, each its own field. The minimap (`map_name`, `player`, `minimap`) is not one:
    it is read every tick, since the path arrow shows "open the minimap" after 3 s without
    a map name, and a minimap read only on its slot would flash that mid-trip after a map
    load.
  - `GRACE = 4`: ticks a part stays due after it was last on screen.
  - `due(turn: int, seen_at: dict[str, int]) -> frozenset[str]`: each part of OPTIONAL
    whose `turn - seen_at[part] <= GRACE`, plus `OPTIONAL[turn % len(OPTIONAL)]`.
  - `found(r: Reading) -> set[str]`: the parts of OPTIONAL whose field is not None.
  - `read_all(frame, t, due: Collection[str] = OPTIONAL) -> Reading`: a part not in
    `due` is not read, and its field is None. EXP, level, job and the minimap are read
    always.
    The default reads everything: every existing caller and test is unchanged.
- Produces, in `app.Tick`: `turn: int = 0`, `seen_at: dict[str, int] =
  field(default_factory=dict)`. `run` calls `read_all(..., now, due(self.turn,
  self.seen_at))`, then sets `seen_at[p] = turn` for `p in found(reading)`, and adds 1 to
  `turn` on every tick that grabs a frame.

Why one in four, with a grace: an open window is read every tick (it was just seen), so
the class helper's marks and the quest helper's panel follow it as today. A closed one
costs one search per four ticks; opening it shows within 2 s. The grace keeps a
window whose read misses now and then (the fullscreen tracker) from vanishing for four
ticks after each miss.

## Not in this plan (decide after Task 6)

- **A worker thread for capture and read.** It would free the UI thread (box drags and
  menus stay smooth) but reads no faster, and readings would arrive late against the
  game. Costs: the module caches (`glyphs._last_hit`, `_last_spot`, the OCR caches) and
  Vision become cross-thread, Qt updates must hop back to the UI thread, and a slow read
  must be dropped, not queued. Not worth it while the main cost is the read itself; the
  cheaper step first is spacing ticks: restart a single-shot timer after each tick with
  `max(_TICK_MS, 2 × that tick's cost)`, so the UI thread is free at least half the
  time (a few lines in `main` and `Tick`).
- **Half-resolution coarse search** in `window.align`: about 23 ms off the one search
  Task 3 leaves per tick (28 ms for six anchors instead of 140, so about 5 ms for the
  one). Needs `COARSE_MIN` recalibrated on every window fixture and the owner's grabs,
  and a test that the half-resolution peak lands within 2 px of the full one.
- **Reading the tracker's miss on fullscreen** (12 of 14 grabs): calibrate its anchor
  on Mac fullscreen fixtures.
